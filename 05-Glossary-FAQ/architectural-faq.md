# ❓ Архитектурный FAQ (Architectural FAQ)

> **Назначение:** Ответы на частые архитектурные вопросы, обоснование ключевых инженерных решений и практическое руководство для быстрого старта новых проектов.

---

### В: Почему Payload CMS 3.0, а не Strapi, Directus или WordPress?
**О:** Payload 3.0 работает непосредственно внутри рантайма Next.js App Router как единый монолит, разделяющий базу данных, серверные компоненты и типы TypeScript. Это исключает необходимость в отдельном Node.js сервере, сокращает задержки (TTFB) до минимума и обеспечивает мгновенный On-Demand Revalidation.

---

### В: Почему PostgreSQL с адаптером Drizzle, а не MongoDB?
**О:** Реляционная модель данных идеальна для мультиязычных коллекций (отдельные таблицы локалей), строгой ссылочной целостности (FK) и надежной работы со связями (Категории ➔ Проекты ➔ Медиа). Drizzle обеспечивает высокую производительность и полную типобезопасность.

---

### В: Как работает мультиязычность без префиксов в URL (`/about` вместо `/en/about`)?
**О:** Текущая локаль сохраняется в cookie `NEXT_LOCALE` и определяется через заголовок браузера `Accept-Language` в Next.js Middleware. Это обеспечивает чистые, неизменные канонические ссылки для SEO и AI-агентов. При необходимости переопределения используется query-параметр `?lang=he`.

---

### В: Зачем сайту одновременно `llms.txt`, MCP, ACP и Markdown Negotiation?
**О:** Это формирует полную трехуровневую экосистему AI-готовности:
1. **`llms.txt`:** Для высокоуровневого знакомства поисковых и диалоговых агентов с компанией.
2. **MCP (`/.well-known/mcp`):** Для прямого подключения агентов (Claude, Cursor) как к источнику фактов и инструментов.
3. **ACP (`/.well-known/acp.json`):** Для автономных торговых ботов (ChatGPT Shopping) для оформления заказов.
4. **Markdown Content Negotiation:** Для экономии токенов и ускорения скрапинга при отправке `Accept: text/markdown`.

### В: Как правильно запускать новый коммерческий проект на этой архитектуре?
**О:**
1. Клонировать шаблон проекта с настроенным `payload.config.ts` и Tailwind 4.
2. Настроить базу данных Supabase PostgreSQL и Vercel Blob.
3. Заполнить базовый контент через `defaultContent.ts` и `scripts/seed.ts`.
4. Развернуть на Vercel и подключить домен через Cloudflare DNS с SSL и WAF.
5. Провести аудит автономным QA-агентом ([[qa-website-auditor-skill|QA Website Auditor]]) и проверить скоринг на `isitagentready.com`.
