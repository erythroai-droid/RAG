# 🔄 Регламент проверки и установки обновлений плагинов и скиллов

#plugins #skills #updates #policy #automation #rules

> **Назначение:** единые правила для всех AI-агентов (Antigravity, Cursor, Claude Code, Codex, Grok) по поддержанию установленных плагинов и скиллов в актуальном состоянии и фиксации всех изменений в [[plugins-skills-registry]].

---

## 1. Обязательное правило ведения реестра

Любой агент, который устанавливает, обновляет или удаляет плагин/скилл (глобально или в проекте), **обязан**:

1. Внести или обновить запись в [[plugins-skills-registry]] в соответствующем разделе агента:
   - имя плагина/скилла и директория установки;
   - текущая версия и/или короткий SHA коммита;
   - источник (URL GitHub-репозитория или Marketplace);
   - список включённых скиллов / MCP-серверов;
   - способ и дата последней проверки обновлений.
2. Записать краткую строку в раздел «Журнал изменений реестра».
3. Зафиксировать изменения в репозитории базы знаний (`D:\Obsidian\Knowledge-Base`) и запушить в `origin main` согласно [[obsidian-git-sync-rule]].

---

## 2. Правила периодической проверки обновлений

### 2.1. Плановая проверка
- **GitHub-плагины с автоматизацией** (например, `modern-web-guidance-plugin`): проверяются автоматически по cron-расписанию через локальный sidecar Antigravity.
- **Все остальные плагины и скиллы из [[plugins-skills-registry]]**:
  - **Рекомендуемый цикл:** не реже **1 раза в месяц** (или по запросу пользователя «проверь обновления скиллов/плагинов»).
  - **Триггер по событию:** если плагин/скилл возвращает ошибки устаревшего CLI/API, предупреждения о новой версии или перед началом крупной задачи в домене этого плагина (Next.js/Vercel, Supabase, Figma, UI/UX, Chrome/Web Platform).

### 2.2. Как проверять наличие обновлений
- **Для GitHub-репозиториев:** сначала лёгкая проверка через `git ls-remote <repo-url> HEAD` (сравнить SHA с последним зафиксированным коммитом); клонировать (`git clone --depth 1`) только если коммит изменился.
- **Для Marketplace-плагинов (Antigravity / Cursor / Claude Code):** проверять обновления через встроенный Marketplace / менеджер плагинов соответствующего агента. **Не переписывать вручную системный `config.json` Antigravity.**
- **Для CLI-обёрток с `@latest`** (например, `npx -y modern-web-guidance@latest`): сам корпус гайдов подтягивается в актуальной версии при каждом вызове, но локальный `SKILL.md` и вспомогательные файлы всё равно нужно проверять на обновления в репозитории.

---

## 3. Протокол безопасного обновления

При обнаружении новой версии плагина из GitHub:

1. **Проверить diff перед заменой:**
   - сравнить `version` в `plugin.json` / `SKILL.md` и список изменённых файлов;
   - убедиться, что не пропали существующие скиллы и не сломалась структура каталога.
2. **Сохранить агент-специфичные метаданные (критично для Antigravity):**
   - при обновлении `plugin.json` в `~/.gemini/config/plugins/<dir>/` сохранять локальные поля `name` (во избежание коллизий пространства имён), `displayName`, `logo` (и локальный файл `assets/logo.svg`, если он указан), `suggestedPrompts`;
   - удалять неподдерживаемые верхнеуровневые поля вроде `$schema`, если загрузчик их игнорирует.
3. **Очистить временные каталоги** после копирования обновлённых файлов.
4. **Проверить идемпотентность** (повторная проверка должна возвращать `up-to-date`).
5. **Обновить [[plugins-skills-registry]]** новой версией, коммитом и датой проверки, и выполнить `git push` в базу знаний.
6. **Отчитаться пользователю** кратко: было → стало, коммит, ключевые изменения (добавленные/изменённые скиллы и гайды).
